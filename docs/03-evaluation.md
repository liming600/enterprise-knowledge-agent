# 03 评估报告

## 可复现验证
在项目根目录运行 `python -m unittest discover -s tests -v`，最近一次完整运行 75 项通过，实际输出见 `examples/test-results.txt`。运行 `python examples/generate.py` 重新生成离线记录 `examples/runs.json`。记录保存输入、输出、状态、引用、缺口和完整工具轨迹。

| 验收项 | 预期 | 证据 |
|---|---|---|
| 明确答案 | D03 原文与 5 天 | runs.json：明确答案；test_single |
| 冲突 | D01、D02 两个期限及追问 | runs.json：文档冲突；test_conflict_and_quotes |
| 资料外 | insufficient，不编造 | runs.json：资料外；test_missing |
| 改写 | 报账/几天匹配报销 | runs.json：改写；test_paraphrase |
| 追问 | 历史年假与省略主题问题 | runs.json：上下文追问；test_followup |
| 工具失败 | tool_error，缺口明确 | runs.json：工具失败；test_failure |
| 替换原文 | 45 天替换后答案随之变化 | test_document_change |
| 步数上限 | incomplete | runs.json：步数上限；test_limit |
| 候选未读 | incomplete，不能提前作答 | test_missing_read |

真实模型路径见 `examples/real-runs.json`：该记录产生于安全层更新之前，11 组均通过当次的状态、预期关键词、原文精确匹配及轨迹存在检查，覆盖明确答案、报销冲突、改写、上下文追问、资料不足、工具失败、文档替换前后、中文数字冲突、允许/禁止冲突及单文档语义冲突。资料不足案例实际有多次补充搜索；工具失败由 `fail=True` 模拟注入，模型收到失败结果后继续决策，不能视为真实外部服务故障。模型输出有随机性，记录只证明当次运行；更新安全层后的真实模型验证见下文。

## 失败与局限
原项目 DeepSeek 接口曾返回 HTTP 402；中转接口可用性依赖账户和网络。混合召回仍有阈值和数量限制，冲突检测使用有限的数值单位、允许/禁止规则及模型冲突提示；模型可能漏判或误报，不同适用条件也可能被保守标记为冲突。最终事实直接复制已读取原文，但程序不能证明原文一定与用户问题完全相关或适用。缺少大规模语料、复杂上下文及真实企业数据测试。离线测试不能替代模型效果评估。

## 身份、版本与记忆

`tests/test_store.py` 验证跨部门隔离、调岗后的权限变化、文档新增版本和回滚、记忆隔离与删除、密码修改和会话失效。`tests/test_http.py` 使用独立临时数据库与本机 HTTP 服务，验证匿名访问被拒绝、员工不能调用管理员接口、也无法通过问答获取其他部门文档。测试数据均为合成资料；未进行生产级渗透测试或高并发测试。

## 批量管理验证

`tests/test_bulk.py` 验证员工批量导入失败时不部分提交、管理员不可被批量更改、多部门访问范围、批量授权失败回滚、部门重命名同步，以及重复初始化不改变数据。`tests/test_http.py` 验证员工不能调用批量部门和授权接口。

## Word 解析验证

`tests/test_word.py` 验证段落、表格内文字、制表符和换行，以及损坏、空文档和超限输入；`tests/test_http.py` 验证管理员解析成功与员工拒绝访问。另对原项目中一份现有 DOCX 本地解析成功（316 字符）；未验证复杂布局、图片、扫描件或加密文档。

单个新增员工由管理员接口验证，部门标签通过页面验证搜索、回车选择及删除；服务端仍校验所有选项属于部门目录。默认管理员不要求部门。

## 会话与引用

`tests/test_conversations.py` 验证会话上下文隔离、记忆删除和权限变化后的历史回答隐藏；`tests/test_http.py` 验证跨用户会话读取和写入被拒绝，以及回答引用被保存。

## 调岗、更名与批量变更边界

`tests/test_bulk.py` 验证只调部门保留身份、只改身份保留部门、跨部门文档权限即时变化、部门更名影响预览、名称冲突、预览后授权变化导致提交拒绝；`tests/test_http.py` 验证未预览直接提交被拒绝，以及问答期间调岗不返回旧权限资料。

## 摘要与混合检索

`tests/test_memory_hybrid.py` 覆盖分片原文、BM25 和向量融合、降级、摘要缓存和删除、并发记忆删除及用户隔离、超预算状态。`examples/real-runs.json` 的真实运行覆盖多个问答场景，语义向量可用时模式为 dense_embedding；`examples/memory-run.json` 为模型摘要的合成数据运行。该样例只证明接口连通和单次流程，尚无大规模召回率、摘要质量或延迟评测。

`tests/test_security.py` 使用合成输入和模拟动作验证用户与文档注入、记忆污染、模型动作及参数校验、重复动作、调用预算、超时和会话清理隔离。规则为启发式检测，测试通过不能证明覆盖所有提示词注入手法。

### 真实模型安全专项（2026-11-04）

运行 `python examples/verify_security_real.py`，输入均为合成资料，实际输入、响应、调用预算和逐步轨迹保存在 `examples/security-real-runs.json`。本次 6 个案例检查通过：正常问题完成并精确引用；直接注入在模型调用前拦截（0 次模型调用）；相关注入文档被隔离并返回未完成；历史中的注入文本被过滤后正常完成；设为 1 步的执行上限返回未完成；模拟检索故障后返回工具失败。正常问答实际执行 3 次模型调用、2 次工具调用及 1 次向量请求，检索类型为 `dense_embedding`。服务方返回的 token 用量与其他预算数据一并记录于运行结果。

这些案例验证的是系统与真实模型协作时的处理结果。直接注入及被隔离文档没有发送给模型，不能据此证明模型能抵抗此类攻击；执行上限案例为测试配置的 1 步，默认上限仍为 8 步；工具故障为主动注入故障，并非实际服务宕机。其他变形注入、长时间运行和大规模对抗样本仍需评测。

## 本轮引用与冲突修复

`tests/test_evidence.py` 覆盖模型编造数字、伪造相似文档 ID、中文数词、允许与禁止、单文档内部冲突、模型提示的非数值冲突、多文档关系不明、无关引用、替换资料、工具错误后的模型决策和执行上限。最终输出由读取到的原文构造，故模型伪造的事实不会直接进入答案；检索相关性仍不能得到形式化保证。测试命令输出见 `examples/test-results.txt`。
