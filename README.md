# 知序：企业知识问答 Agent
需要 Python 3.10+，无第三方依赖（见 `requirements.txt`）。在项目根目录运行 `python src/server.py`，访问 http://127.0.0.1:8000；测试：`python -m unittest discover -s tests -v`。默认离线演示。真实模型配置可复制 `.env.example` 为 `.env` 并填写密钥，也可通过环境变量设置。支持原项目的 `DEEPSEEK_*`、`RELAY_*`，用 `LLM_PROVIDER=deepseek`（默认）或 `relay` 选择。环境变量优先于文件。

在本机复用原项目配置时，在本项目目录运行：

```powershell
$env:KNOWLEDGE_ENV_FILE = (Resolve-Path '..\.env').Path
$env:LLM_PROVIDER = 'relay' # 或 deepseek
python src/server.py
```

这是显式引用原项目配置，密钥不会复制进本项目。独立交付时应自行配置 `.env`。参考原项目 backend/app/retrieval、verifier_agent 及 llm/client.py。资料为合成数据。离线模式仅验证流程，不能证明真实模型决策。真实模型记录见 `examples/real-runs.json`；最终事实以已读取原文的逐字摘录输出，但相关性与冲突的语义判断仍有局限；本地服务仅供演示。实际投入约 3 小时。项目题目为企业知识问答 Agent；题号以考核方提供的信息为准。仓库地址：https://github.com/liming600/enterprise-knowledge-agent 。最终 commit SHA 可在仓库中运行 `git rev-parse HEAD` 查看。

## 身份、知识库与记忆

首次启动会初始化管理员 `admin`，初始密码 `admin123`。登录后请在「账户设置」修改密码；修改会使该用户的所有会话失效。管理员在「管理中心」先批量导入部门，再通过表单单个新增或通过 CSV 批量导入员工；勾选非管理员员工后可单独或批量调整部门或提升为管理员；未选择的字段保持不变，提交前逐人预览权限变化。现有管理员账号不能在此修改。员工仅可读取授权给「公共」或所属部门的当前版本文档，管理员可读取全部部门。服务端每次问答重新按当前身份过滤资料，不接受浏览器指定身份或文档范围。

管理员可上传 `.docx`、UTF-8 的 `.txt` / `.md` 文件或直接粘贴正文，指定归属部门和版本日期，并在输入框中搜索并选择一个或多个可访问部门，已选部门显示为可删除标签。文档按归属部门筛选，支持批量替换所选文档的访问范围；历史版本共用当前访问范围。选择「上传新版本」会保留旧版本；「查看历史版本」可将旧版本重新设为生效版本。现有文档的部门和标题在新增版本时保持不变。回答时使用当前会话近期问题及较早问题的摘要，不把历史回答或摘要作为制度事实来源。用户历史记录会保存问题与回答，部门变更后历史不会自动清除。

数据保存在 `data/workspace.db`，已由 `.gitignore` 忽略；首次初始化时导入 `data/docs.json` 的三份公共示例资料。删除数据库会丢失账户、文档版本和记忆，不建议当作重置操作。账号密码使用 PBKDF2 哈希，登录令牌使用 HttpOnly、SameSite Cookie；本应用仅供本机演示，默认密码、HTTP、本地文件存储及缺少安全审计和登录限速均不适合生产环境。

真实模型模式会把问题、历史问题、摘要和读取到的文档片段发送到对话模型服务；语义检索时还会把当前用户可访问的所有文档分片发送到配置的向量服务（默认中转站）。请只使用允许发送的资料。离线演示模式不调用模型或向量服务。

## HTTP 接口与评审入口

浏览器登录后通过 `/api/ask` 提问，接收 `question`、`mode`，上下文由服务端按当前账户读取。`/api/documents` 和 `/api/memory` 仅返回当前用户可访问的数据；用户和版本管理接口要求管理员登录。输出包括 `status`、`answer`、`citations`、`gaps` 和 `trace`。用例见 `tests/`；`python examples/generate.py` 可重建离线问答记录。旧的无登录 POST `/` 接口已移除。

需求、设计和测试映射见 `docs/01-requirements.md`、`docs/02-solution.md` 和 `docs/03-evaluation.md`。文档冲突检测覆盖同单位数值差异、允许/禁止等有限规则和模型报告的潜在冲突；多个相关文档无法可靠判断关系时会请求澄清，并非完整语义矛盾检测。最终事实使用已读取的原文，不直接展示未经验证的模型事实陈述。

## 批量管理操作

1. 在管理中心的「部门目录」逐行输入或上传 TXT/CSV 部门名称，点击批量导入。重命名部门前会列出受影响的员工、文档和授权，确认后同步修改所属员工、文档归属及授权；公共部门不可重命名，已有部门名称不能直接合并。
2. 员工 CSV 使用 UTF-8，表头固定为 `username,password,department`，例如：

```csv
username,password,department
zhangsan,Password123,财务部
lisi,Password456,人事部
```

员工初始密码至少 8 位，部门须预先导入。重复用户名、未知部门或其他无效行会导致整个批次取消；CSV 包含密码，请妥善保存并在导入后按实际需要销毁。导入的账号均为员工；管理员可按用户名、部门筛选并选择一人或多人，分别修改部门或角色；预览确认前不会保存，现有管理员不可修改。升级为管理员后不能通过界面撤销。
3. 新建文档时选择一个归属部门（分类用途），再输入搜索并选择一个或多个可访问部门；勾选“公共”表示所有员工均可访问。在文档列表中筛选归属部门并勾选文档，可批量替换访问范围。更改权限作用于该文档的全部版本。

既有数据库启动时会自动迁移部门目录和原有文档权限；迁移只执行一次。

## Word 文档解析

管理员在「上传文档 / 新版本」选择 `.docx`，系统在本地解析正文并填入文本框；检查和修订后，选择归属部门、可访问部门及版本日期，再点击保存。新版本同样支持上传 Word。文件上限 4 MB，正文上限 20 万字符；只保存解析后的文本，不保存原始 Word 文件。解析覆盖正文段落、表格内文字、制表符和换行，不保留表格布局、格式、页眉页脚、图片、批注及脚注，也不支持扫描件 OCR、加密文档或旧版 `.doc`，请先转换为 `.docx`。解析结果应由管理员核对。

管理员是账号身份而非部门；新初始化的管理员默认不设部门。已有真实部门及其关联权限会保留；旧演示数据中的部门目录名称不会自动删除。单个新增员工和批量导入均需先建立所属部门。

界面顶部固定显示主要功能入口；左侧「本页导航」可跳转到当前功能的关键区域。管理中心按部门筛选文档，点击文档对应的「查看历史版本」可在文档下方展开版本时间线，并将历史版本设为当前版本。

## 知识问答会话

知识问答左侧可新建或切换会话，每条回答下方显示实际读取的参考文档、版本日期和原文；没有证据时显示无可引用文档。每个会话独立使用近期未删除的问题和较早问题的摘要作为上下文，聊天记录按用户保存。聊天顶部可清除当前会话的记忆和摘要，不删除聊天记录，也不影响其他会话。历史回答使用当时读取的版本快照；若当前用户不再有权访问其中任一文档，该回答和检索记录会隐藏。最终答复采用原文摘录以避免模型随意改写；自动相关性筛选仍可能漏召回或选到无关片段，须人工核验。

### 员工调岗与更名边界

员工管理中「保持原部门」和「保持原身份」互相独立；支持按姓名和当前部门筛选，多次筛选间的勾选保留，提交前预览逐人原值、新值与新增/失去访问的文档。调岗后服务端下一次请求立即应用新权限，原有登录会话无需重登，公共资料继续可访问。管理员仍不能在此降级；对所有已选员工都不发生变化的提交会被拒绝。

部门更名保留同一部门的员工、文档归属、授权和历史版本关系，不自动合并到已有部门。预览之后如果员工、文档或授权发生变化，提交会拒绝并要求重新预览。问答执行期间若访问权限缩小，该次回答会被丢弃，要求按新权限重新提问。

## 会话摘要与混合检索

- 记忆：保留最多 6 条近期问题（约 3500 UTF-8 字节，最新一条完整保留），较早问题自动摘要并按会话持久化；真实模式调用对话模型，离线模式或模型失败时使用截取式摘要。摘要不包含历史回答，也不作为制度事实依据。聊天界面支持清除当前会话的记忆和摘要。截取式摘要及模型摘要都可能遗漏细节。
- 上下文限制：使用 UTF-8 字节数作为保守预算近似，不等于精确 Token 计数，也不会自动读取供应商模型窗口。单次模型输入超过 48000 字节时返回 incomplete；不会对过大的工具结果继续自动压缩。超过 4 批的旧记忆或摘要模型失败时降级为截取式摘要。

## 安全与运行预算

问题、历史记忆、文档及模型动作均视为不可信输入：对常见注入和泄密指令进行启发式识别；疑似恶意文档在检索及向量调用前隔离；模型动作仅允许搜索、读取已检索且已授权的文档或结束。最终事实仍由已读原文组装。拦截和隔离结果会明确显示；相关资料被隔离时可能返回未完成。该识别不是完整的提示词注入防护，可能误拦或漏掉变形攻击，不能替代生产环境的权限隔离、审计和人工复核。

每次问答共享预算：最多 8 步、6 次工具调用、8 次模型调用（含摘要）、8 次远程向量请求；同一动作及参数最多执行 2 次。模型和向量的累计输入不超过 120000 UTF-8 字节，单次模型输入不超过 48000 字节；达到限制返回未完成。模型输出请求上限为决策 1200、摘要 500 token；供应商有返回 usage 时会记录。120 秒为检查点和网络超时共同约束，并非强制中断进程的精确截止时间。
- 检索：先进行部门权限过滤，对文档分片后并行计算 BM25 和向量相似度，通过 RRF 融合。真实模式使用 `RELAY_BASE_URL`、`RELAY_API_KEY` 和 `EMBEDDING_MODEL` 的 OpenAI 兼容 embeddings 接口；离线模式及接口失败时用本地字符向量，不能当作语义模型效果。返回最多 8 个分片、每份文档最多 2 个；知识库超过 128 个分片时明确返回 incomplete。阈值和召回上限均为演示配置，不能保证找全所有冲突。
- 真实接口样例：`examples/real-runs.json` 和 `examples/memory-run.json` 是合成数据的实际运行结果；模型和网络情况变化时结果可能不同。混合检索未接入持久化向量数据库，向量缓存在进程内，版本切换或重启后重新计算。

## 引用安全、冲突与验证

真实模式仍由模型逐步选择搜索、读取、追加搜索或结束；最终 factual 答复由服务端以已读取的文档原文组装，不直接采用模型自由生成的事实描述。文档 ID 使用完整匹配；未检索、未读取候选、无有效引用或超出步数上限不会返回完成。若检索到资料但模型明确表示无法确定，返回资料不足。

冲突规则识别同单位不同数值（含常见中文数词）、允许/禁止等相反表述及模型报告的潜在冲突，可能因适用范围不同而误报；多份相关文档无法可靠判断关系时会保守请求澄清。该方法不是通用事实蕴含或语义矛盾检测，查询词匹配、分片和召回上限仍可能漏掉冲突；大段原文也需要人工检查是否真正回答问题。

运行 `python examples/generate.py` 生成 12 组离线记录；`python examples/evaluate_real.py` 会调用配置的真实模型和向量服务并覆盖 `examples/real-runs.json`，仅使用合成案例，可能产生网络费用。11 组真实记录包含正常、冲突、改写、追问、资料不足、模拟工具失败、文档替换以及单文档语义冲突；其中工具失败通过参数注入，并非真实外部服务故障。运行 `python examples/run_tests.py` 生成 `examples/test-results.txt`。
